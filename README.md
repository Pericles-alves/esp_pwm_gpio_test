# ESP32-S3 PWM/GPIO Hardware Simulation

This project is a small ESP-IDF application for validating another application
against a simulated machine controller running on an ESP32-S3. It generates
four PWM signals that represent rollers or motors and drives four digital
outputs that represent machine status LEDs. The firmware periodically changes
between a normal production state and a fault state, allowing the external
application to be tested without the complete physical machine.

## Behavior

The controller runs the following repeating sequence:

1. A production cycle starts and assigns a random PWM frequency to each roller.
2. Each LED is assigned one of three states: `1` (ON), `2` (OFF), or `3`
   (BLINKING at 20 Hz).
3. The machine remains in `RUNNING` for approximately 15 seconds.
4. A random roller is stopped by setting its PWM duty cycle to zero. The
   corresponding LED is forced to state `3` and blinks at 20 Hz while the
   machine is in `FAULT`.
5. After approximately 15 seconds, the fault is cleared and a new cycle starts.

The serial log reports the selected frequencies, numeric LED states, machine
state, stopped roller, and blink mask. This makes the firmware state observable
while the external application monitors the GPIO signals.

## GPIO mapping

| Signal | GPIO | Description |
| --- | ---: | --- |
| PWM roller 0 | 4 | LEDC channel 0 |
| PWM roller 1 | 5 | LEDC channel 1 |
| PWM roller 2 | 6 | LEDC channel 2 |
| PWM roller 3 | 7 | LEDC channel 3 |
| Status LED 0 | 18 | Digital output; state 1/2/3 |
| Status LED 1 | 17 | Digital output; state 1/2/3 |
| Status LED 2 | 16 | Digital output; state 1/2/3 |
| Status LED 3 | 15 | Digital output; state 1/2/3 |

The LED state values are:

| Value | State | Electrical output |
| ---: | --- | --- |
| 1 | ON | Constant HIGH |
| 2 | OFF | Constant LOW |
| 3 | BLINKING | 20 Hz square wave, 50% duty cycle |

Connect the GPIOs to the inputs of the application under test using a common
ground. Do not connect external loads directly to the ESP32-S3 pins; use the
appropriate driver, resistor, transistor, or level shifter for the target
hardware.

## Requirements

- ESP32-S3 development board
- ESP-IDF 5.5.1
- USB cable and a serial monitor
- A host with the ESP-IDF tools available in `PATH`

The target and ESP-IDF version are recorded in [dependencies.lock](dependencies.lock).

## Build and flash

From the repository root, set the target, build the application, flash it, and
open the serial monitor:

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p PORT flash monitor
```

Replace `PORT` with the serial device for the development board, for example
`/dev/ttyACM0`. Press `Ctrl-]` to exit the monitor. The project name is
`esp_pwm_gpio` and the application entry point is [main/main.c](main/main.c).

## Expected log output

At startup, the monitor prints the PWM configuration and then periodic status
messages similar to:

```text
[RUN] PWM = [.... .... .... ....] LEDs = [1 2 3 1] BlinkMask=0x4
[FLT] PWM = [.... ....    0 ....] LEDs = [1 2 3 1] BlinkMask=0x4
```

The exact values vary because the test pattern is generated with the ESP32
hardware random-number generator. `FLT` identifies the simulated fault and
the zero PWM entry identifies the stopped roller. The LED values in the log
are the state values from the table above.

## Configuration points

The GPIO assignments, number of outputs, PWM frequency limits, and cycle timing
are defined near the top of [main/main.c](main/main.c). Change these constants
to match the electrical interface of the application being tested, then rebuild
and flash the board.

The current implementation uses 50% duty cycle for active PWM channels and
configures each channel with its own LEDC timer. The faulted channel keeps a
low-frequency timer configuration but has zero duty cycle, so the external
application observes the roller as stopped. LED transitions are scheduled by
an ESP timer every 25 ms, producing a 20 Hz full blink cycle.
